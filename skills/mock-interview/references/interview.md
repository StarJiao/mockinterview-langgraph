# 面试流程

## 规划

接收 focus（一个或多个方向）、题数（默认 3）、可选简历、一个或多个 JD、学习状态和预定题目。题数足够时每个方向至少一个考点，题数不足时按用户优先级分配并说明覆盖范围。每个考点具体到机制或决策，避免重复考同一缺口。

每个计划项保留 topic、direction、2–4 个 points、difficulty（1–5）、source（jd/resume/state-snapshot）以及 evidence：

- project：简历或用户明确描述做过。
- tested：有实测回答、复测、评分或复盘记录。
- theoretical：仅 JD 要求、学习中、未学或没有证据。

只有 project/tested 才能标 weak=true。有证据的薄弱点优先纳入，但不能挤掉其他方向；题数不足以覆盖全部时说明取舍。theoretical 不等于薄弱，先出难度不高于 2 的基础验证题。其余题目适度递进。只向候选人展示简要考查方向，不展示内部要点。

## 主问

按计划顺序生成，不因上一题表现擅自换主题。先给 1–3 句必要背景，再问一个具体机制或决策。避免“从 A/B/C 分别详述”、多个子问题和暗示答案。内部保留及格（3 分）、优秀（5 分）锚点以及 2–3 个可选追问方向。

没有源码或项目材料时，不要求候选人报出具体文件或字段。题目需要的假设必须明确提供，例如相同 TTL 并不意味着同时过期。

## 每轮快评与决策

记录最新回答意图 answer / clarification / give_up；快评则累计本题全部回答，记录 covered、missed、score（0–100 的覆盖程度，不是最终能力分）、sufficient、has_new_evidence、next_target。

“我不知道具体文件，先看调用链”仍是作答；质疑前提、给出替代方案也是作答。作答同时请求澄清时先处理澄清，但保留已提供的证据。短回答不因短扣分。

按以下顺序决定下一步：

1. 明确不会或跳过：结束本题。
2. 请求澄清：未用澄清机会时解释原条件或明确补充最少假设，再请其回答原问；已经澄清一次仍无法继续时结束，标记评估受限。澄清不算技术追问，不据此认定不会。
3. 正式追问已达 3 次：结束。
4. 核心证据充分：结束。
5. 覆盖分低于 50、已给过补充机会且后续实质回答没有新增证据：结束。补充后的澄清请求不算消耗了实质回答机会。
6. 覆盖分低于 50 且尚未给过补充机会：给一次针对性补充机会；其他情况问一个尚缺的核心证据。两者都计入 3 次追问上限。

追问衔接完整对话，先说明必要背景，只确认一个缺口。新增有效机制、边界、纠正或止血方法都可算新证据；重复表述不算。不要不断换措辞索取同一个标准答案。

本题结束后用一句自然的话收尾，冻结问答用于评分，再进入下一题。正常测评时将详细讲解留到报告；用户要求即时反馈时遵从并记录已给提示。用户提前结束整场时仅报告实际完成与已回答部分。
