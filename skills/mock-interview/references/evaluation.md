# 评分与报告

每题根据全部已提交问答评分，追问中补全或纠正的内容同样有效。先列证据，再定分。固定四维：技术准确性、机制深度、表达结构、迁移与场景应用。

每个维度包含 assessments、score、evidence：

- assessments：kind、round_index（从 1 开始）、candidate_quote（该轮候选人原文连续片段）、explanation。
- kind：correct（明确正确）、incorrect（明确错误）、asked_not_expanded（已问但未展开）、not_asked（未问到）、unclear_question（题意不清或提问带偏）。
- score：1–5 的整数或 null。结合本题 3 分/5 分锚点；仅有 not_asked/unclear_question 或缺乏可评价证据时必须为 null。
- evidence：分别写“原文：”“评分理由：”“改进建议：”，给出具体可执行的改进；充分时如实说明，不编造缺点。

验证回合存在、引文确实在对应回答中、四维恰好齐全且不重复、数字分有实际可评价证据。没有可引用内容时引文用空字符串并说明，不伪造引用。语音转写、大小写或拼写不影响明确语义时不扣分。

已问但没展开可以影响深度，不自动等于技术错误。没要求完整治理方案，就不能因为缺少回滚、权限、重试等内容扣分；这些只能列为后续考查建议。面试官的假设不属于候选人的主张；后补条件只评价后续回答。

四维都有分时相加，显示 x/20。任一维度未评估时不给单题总分，显示已评估 n/4。评分失败与证据不足不同：前者待补评，后者有效结果是 null。

## 报告布局

1. 方向、题数、完成状态、工作方式；仅有真实记录时列版本和用量。
2. 整场汇总：完成题数、已有评分数、缺分数，明确是单题汇总。
3. 复习建议：从已评估分数和证据中找优先复习考点、相对薄弱维度；列数字样本数和未评估数。比较时注明各题已评估维度不同的限制。缺失维度不补零，不生成整场总分，也不推广为跨场能力结论。
4. 逐题：考点、难度、主问/追问/澄清、候选人原答、收尾、四维证据与评分；区分未提交与主动空答。

报告可以包含内部评价锚点，但作答前不能展示。用户要求导出时写 Markdown 文件并提供路径；不把原项目自带简历、旧报告或历史问答作为新用户素材。
